## 1. はじめに

### 1-1. 家計ログでできること

「お金がいくら入って、何に使って、今どこにいくら残っているか」を記録し、ひと目で確認できます。

学生のお金の管理には、次のような面倒があります。

- 財布の現金、銀行口座、PayPay など、**お金の置き場所がいくつもある**
- スマホ代やサブスクなど、**毎月決まって出ていくお金**を毎回入力するのが手間
- PayPay で払った分を、**1 件ずつ手で打ち直す**のが大変

家計ログは、これらの手間を減らすために作られています。

### 1-2. 主な機能

| 機能 | できること | この機能がある理由 |
| --- | --- | --- |
| 収支の記録 | 収入・支出を登録・一覧・編集・削除 | 家計簿の基本。入力ミスを後から直せるようにするため |
| 口座・資産の管理 | 現金・銀行口座・電子マネーごとに残高を表示 | お金の置き場所ごとに「今いくらあるか」を把握するため |
| 資産間振替 | 「口座から財布へ 1 万円」などの移動を記録 | ATM で下ろしたお金は支出ではないので、収支と分けるため |
| カテゴリー | 「食費」「交通費」などで分類 | 何にいくら使っているかを振り返るため |
| 自動収支 | 毎週・毎月・毎年の決まった収支を自動で予定に入れる | 同じ内容を毎回入力する手間をなくすため |
| 予定収支確認 | 自動で作られた予定を「確定」または「キャンセル」 | 金額が変わる月もあるので、勝手に記録せず本人が確認するため |
| スマホ決済データ取込 | PayPay の利用明細 CSV をまとめて登録 | 1 件ずつ打ち直す手間をなくすため |
| カレンダー | 日ごとの収支をカレンダーで表示 | 「いつ使ったか」を直感的に見るため |
| 分析・レポート | 月ごと・カテゴリーごとの収支をグラフで表示 | 使いすぎている月や項目に気づくため |

## 2. ご使用前の準備

家計ログは、**ご自分のパソコンの中でサーバーを起動し、ブラウザから開いて使う**アプリです。
ここでは **Mac で初めて使う方** を想定して説明します。

> **コマンドの入力場所**
> 以下のコマンドは、すべて Mac の「ターミナル」アプリに入力します。
> （Finder →「アプリケーション」→「ユーティリティ」→「ターミナル」）

### 2-1. 必要なもの

| 必要なもの | 用途 |
| --- | --- |
| Mac | このアプリを動かすパソコン |
| **JDK 21** | Java で作られたこのアプリを動かすため |
| **PostgreSQL** | 家計簿のデータを保存するため（データベース） |
| Web ブラウザ | 画面を表示・操作するため（Chrome、Safari など） |

### 2-2. この手順が想定している状況

2 章と 3 章の手順は、次の状況を想定して書いています。
当てはまらない場合は、各手順の「想定していること」を確認してください。

| 項目 | 想定 |
| --- | --- |
| 手順を行う人 | このアプリを **自分のパソコンで初めて動かす人**（開発メンバー、先生、動作確認をする人など） |
| パソコン | **Mac**（macOS） |
| 前提の知識 | ターミナルにコマンドを貼り付けて実行できる程度 |
| 事前に済んでいること | Homebrew がインストール済み / GitHub アカウントを持っている |
| まだ済んでいないこと | JDK 21・PostgreSQL のインストール、アプリのダウンロード、データベースの作成 |
| ゴール | ブラウザでログイン画面を開き、ログインできる状態 |

> **すでに JDK 21 や PostgreSQL が入っている場合**
> 該当する手順は飛ばしてかまいません。「完了の目安」の状態になっているかだけ確認してください。

### 2-3. 必要なソフトをインストールする

**想定していること**

- [Homebrew](https://brew.sh/ja/)（Mac 用のソフト管理ツール）がインストール済み
  - 入っているかは `brew --version` で確認できます。表示されない場合は、先に公式サイトの手順で入れてください
- JDK 21 と PostgreSQL は、まだ入っていない

Homebrew を使うのは、コマンド 1 行でインストールでき、手順を正確に伝えやすいためです。

**① JDK 21 と PostgreSQL をインストールする**

```bash
brew install openjdk@21
brew install postgresql@16
```

※ PostgreSQL のバージョン（16）は一例です。他のバージョンでも動きます。その場合は、以降のコマンドの `16` も読み替えてください。

**② Mac に JDK 21 の場所を登録する**

Homebrew で入れた JDK は、そのままでは `java` コマンドとして使えないため、次のコマンドで登録します（Mac のパスワードを聞かれます）。

```bash
sudo ln -sfn $(brew --prefix)/opt/openjdk@21/libexec/openjdk.jdk /Library/Java/JavaVirtualMachines/openjdk-21.jdk
```

**③ PostgreSQL を起動する**

```bash
brew services start postgresql@16
```

※ 一度実行すれば、Mac を再起動しても自動で起動します。

**④ 正しく入ったか確認する**

```bash
java -version
psql --version
```

✅ **完了の目安**：`java` は `21` から始まるバージョン、`psql` は `16` から始まるバージョンが表示される。

### 2-4. アプリをダウンロードする

**想定していること**

- GitHub アカウントを持っていて、**このリポジトリを見る権限がある**
  （非公開リポジトリの場合は、作者に招待してもらう必要があります）
- GitHub に **SSH キーを登録済み**
  （まだの場合は、下の「SSH キーを登録していない場合」の方法を使ってください）
- ダウンロード先は、ターミナルを開いたときの場所（ホームフォルダ）

**① GitHub からアプリをコピー（クローン）する**

```bash
git clone git@github.com:Shibakamio2026/Shibakamio2026.git
```

> **SSH キーを登録していない場合**
> 次のコマンドでもダウンロードできます（HTTPS という方法です）。
>
> ```bash
> git clone https://github.com/Shibakamio2026/Shibakamio2026.git
> ```

**② ダウンロードしたフォルダに移動する**

```bash
cd Shibakamio2026
```

※ 以降のコマンドは、必ずこのフォルダの中で実行してください。起動に必要なファイル（`mvnw`）がこのフォルダにあるためです。

✅ **完了の目安**：`ls` を実行すると `pom.xml` や `mvnw` が表示される。

### 2-5. データの保存場所（データベース）を作る

**想定していること**

- 2-3 の手順で、PostgreSQL が起動している
- アプリの設定を変えずに、そのまま動かしたい

アプリは次の設定でデータベースに接続します（`src/main/resources/application.properties` に書かれています）。
この手順では、**この設定に合うデータベースとユーザーを用意します**。

| 設定 | 値 |
| --- | --- |
| 接続先 | 自分のパソコン（`localhost`）の 5432 番 |
| データベース名 | `shibakamio2026` |
| ユーザー名 | `postgres` |
| パスワード | `postgres` |

**① 接続用のユーザー `postgres` を作る**

Homebrew で入れた PostgreSQL には `postgres` というユーザーがないため、作成します。

```bash
createuser -s postgres
psql -d postgres -c "ALTER USER postgres PASSWORD 'postgres';"
```

※ `role "postgres" already exists` と表示された場合は、すでにあるので次に進んでください。

**② データベースを作る**

```bash
createdb -O postgres shibakamio2026
```

⚠️ 名前は必ず `shibakamio2026` にしてください。アプリはこの名前のデータベースに接続する設定になっています。

作るのは「空の入れ物」だけで大丈夫です。
テーブルやお試し用のデータは、初めて起動したときに自動で作られます。

✅ **完了の目安**：`psql -l` を実行すると、一覧に `shibakamio2026` が表示される。

> **ユーザー名やパスワードを別のものにしたい場合**
> `application.properties` の `spring.datasource.username` と `spring.datasource.password` を、自分で作ったものに書き換えてください。

## 3. 起動と終了

### 3-1. 起動する

**想定していること**

- 2 章の手順がすべて終わっている
- 次のどちらかの方法で起動する

| 起動方法 | 向いている人 |
| --- | --- |
| ターミナルから起動 | アプリを使うだけの人。Eclipse がなくても起動できます |
| Eclipse から起動 | ソースコードを見たり修正したりする人 |

**ターミナルから起動する場合**

2-4 でダウンロードしたフォルダ（`Shibakamio2026`）の中で実行します。

```bash
./mvnw spring-boot:run
```

**Eclipse から起動する場合**

Eclipse にこのプロジェクトを読み込んである前提です。
（まだの場合は「ファイル」→「インポート」→「Maven」→「既存 Maven プロジェクト」で、2-4 のフォルダを選びます）

1. `src/main/java` の中にある `Shibakamio2026Application.java` を右クリックします。
2. 「実行」→「Spring Boot アプリケーション」を選びます。
   （表示されない場合は「実行」→「Java アプリケーション」でも起動できます）

✅ **完了の目安**：ログに `Started Shibakamio2026Application` と表示される。
※ 初回は必要なライブラリをダウンロードするため、数分かかることがあります。

### 3-2. 画面を開く

ブラウザで次のアドレスを開くと、ログイン画面が表示されます。

👉 **http://localhost:8080/login**

※ `localhost` は「自分のパソコン」、`8080` はこのアプリが使う番号（ポート）という意味です。

### 3-3. ログインする

**お試し用のアカウントで使う場合**

すぐに試せるように、お試し用のアカウントが用意されています。

| メールアドレス | パスワード |
| --- | --- |
| `test@example.com` | `password123` |

このアカウントには、カテゴリー「食費」と資産「財布（10,000 円）」が登録済みです。

**自分のアカウントを作る場合**

1. ログイン画面から新規登録画面を開きます。
2. 「ユーザー名」「メールアドレス」「パスワード」「パスワード確認用」を入力します。
3. 「登録」を押します。

### 3-4. 終了する

1. 画面右上の「ログアウト」を押します。
2. ターミナルで `control` + `C` を押すと、アプリが止まります。
   （Eclipse の場合は、コンソールの赤い四角「終了」ボタンを押します）

※ 終了してもデータは消えません。次に起動したときも、続きから使えます。

## 5. 基本の使いかた

はじめて使うときは、次の順番で進めるとスムーズです。

```
① 資産を登録 → ② カテゴリーを登録 → ③ 収支を記録
```

資産とカテゴリーがないと、収支を記録するときに選ぶものがないためです。

### 5-1. 資産（お金の置き場所）を登録する

1. メニューの「口座・資産一覧」を開きます。
2. 「新規資産登録」を押します。
3. 次の項目を入力します。

   | 項目 | 入力例 |
   | --- | --- |
   | 資産名 | 財布、〇〇銀行、PayPay |
   | 資産種別 | 現金 / 銀行口座 / 電子マネー / その他 |
   | 初期残高 | 今その場所にある金額（0 円以上） |

4. 「登録」を押します。

### 5-2. カテゴリーを登録する

1. メニューの「設定」→「カテゴリー登録」を開きます。
2. 「カテゴリー名」に入力します（例：食費、交通費、アルバイト代）。
3. 「登録」を押します。

### 5-3. 収入・支出を記録する

1. メニューの「収支入力」（または「＋収支を記録」）を開きます。
2. 「支出」か「収入」を選びます。
3. 次の項目を入力します。

   | 項目 | 内容 |
   | --- | --- |
   | カテゴリー | 何のお金か |
   | 資産 | どこから払ったか / どこに入ったか |
   | 金額 | 金額 |
   | メモ（任意） | 自由に書けるメモ |
   | 取引日 | お金が動いた日 |

4. 「一度だけ登録」を選んで「登録」を押します。

### 5-4. 記録を確認・修正する

1. 収支一覧画面を開きます（ホームの「すべての履歴を見る →」から開けます）。
2. 期間・カテゴリー・資産・取引種別で絞り込めます。
3. 修正したい行の「編集」を押すと、内容の変更や削除ができます。

## 6. 便利な使いかた

### 6-1. 毎月決まった収支を自動で入れる（自動収支）

スマホ代、サブスク、アルバイト代など、毎回同じ収支に使います。

1. 「収支入力」を開き、カテゴリー・資産・金額を入力します。
2. 「**自動収支として登録**」を選びます。
3. 次の項目を入力します。

   | 項目 | 内容 |
   | --- | --- |
   | 発生間隔 | 毎週 / 毎月 / 毎年 |
   | 開始日 | 最初にお金が動く日 |
   | 終了日（任意） | 終わる日。ずっと続く場合は空欄 |

4. 「登録」を押すと、予定が自動で作られます。

※ 「毎月 31 日」のように、その日がない月は月末の日付で予定が作られます。

**やめたいとき**：「自動収支一覧」で、その行の「停止する」を押します。

### 6-2. 予定を確定する（予定収支確認）

自動収支で作られた予定は、**確定するまで収支の記録には入りません**。
金額が変わったり、その月だけ無かったりすることがあるためです。

1. メニューの「予定収支確認」を開きます。
2. 内容を確認して、次のどちらかを押します。

   | ボタン | 動作 |
   | --- | --- |
   | 確定する | 実際の収支として記録されます |
   | キャンセル | 記録せずに予定を取り消します |

### 6-3. お金を移動したときに記録する（資産間振替）

ATM でお金を下ろした、PayPay にチャージした、などのときに使います。
これは支出ではなく「置き場所が変わっただけ」なので、収支入力ではなく振替で記録します。

1. 「口座・資産一覧」→「資産間振替」を開きます。
2. 「振替元資産」「振替先資産」「金額」「日付」を入力します。
3. 「登録」を押します。

### 6-4. PayPay の利用明細をまとめて取り込む（スマホ決済データ取込）

1. PayPay アプリから、利用明細の CSV ファイルをダウンロードしておきます。
2. 「収支入力」画面の「CSV/スマホ決済データから取り込む →」を開きます。
3. 「取込先の資産」を選び、CSV ファイルを選択します。
4. 「確認する」を押すと、取込結果（プレビュー）が表示されます。
5. 1 行ずつ内容を確認し、必要に応じて次を調整します。
   - 「取り込む」のチェック（取り込まない行はチェックを外す）
   - 種別、カテゴリー、チャージの場合は振替元資産
6. 「登録」を押します。

**自動で判定されるルール**

| CSV の内容 | 判定される種別 | 理由 |
| --- | --- | --- |
| 取引内容に「チャージ」を含む | チャージ（振替） | 口座から PayPay へのお金の移動で、支出ではないため |
| 出金金額がある | 支出 | お金を使った取引のため |
| それ以外 | 収入 | 入金された取引のため |

※ 自動の判定が間違っていることもあるため、登録前に必ずプレビューで確認してください。
※ すでに登録済みの可能性がある行には「重複の可能性あり」と表示されます。

### 6-5. 振り返る（カレンダー・分析・レポート）

| 画面 | 使いかた |
| --- | --- |
| カレンダー | 「← 前月」「翌月 →」で月を切り替え、日ごとの収支を見ます |
| 分析・レポート | 開始月・終了月を選んで「表示」。月ごとの収支とカテゴリー別の集計が表示されます。「見る」で月の詳細グラフを開けます |

※ レポートでは「確定済み」と「予定（未確定）」を分けて表示します。

## 7. 設定

### 7-1. カテゴリーを変更・削除する

「設定」→「カテゴリー登録」の一覧で操作します。

| 操作 | 動作 |
| --- | --- |
| 保存 | カテゴリー名を変更します |
| 無効化 | 今後の入力で選べなくします。過去の記録はそのまま残ります |
| 削除 | 完全に削除します（**一度も使われていないカテゴリーのみ**） |

※ 使用中のカテゴリーを削除できないのは、過去の記録の分類がわからなくなるのを防ぐためです。
資産も同じ理由で、削除ではなく「無効化」で管理します。

### 7-2. アカウント情報を変更する

「設定」→「アカウント管理」で、ユーザー名とメールアドレスを変更できます。

### 7-3. アカウントを削除する

1. 「設定」→「アカウント管理」→「アカウントを削除する」を押します。
2. 本人確認のため、現在のパスワードを入力します。
3. 「アカウントを削除する」を押します。

⚠️ **削除すると、収支・資産・カテゴリーなどすべてのデータが完全に消え、元に戻せません。**

## 8. ご注意ください

- ⚠️ **アプリを起動したまま、ターミナルや Eclipse を閉じないでください。** アプリが止まり、画面が表示されなくなります。
- ⚠️ **お試し用アカウントのパスワードは誰でも知っています。** 実際のお金の記録は、自分で作ったアカウントで行ってください。
- ⚠️ **30 分間操作しないと、自動でログアウトされます。** 入力途中の内容は保存されないのでご注意ください。
- ⚠️ データはご自分のパソコンの中にだけ保存されます。別のパソコンからは見られません。

## 9. 困ったときは

| 症状 | 考えられる原因 | 対処方法 |
| --- | --- | --- |
| `java -version` でバージョンが出ない | JDK の場所が登録されていない | 2-3 の ② を実行してください |
| ブラウザで開いても「接続できません」と出る | アプリが起動していない | 「3-1. 起動する」の手順で起動し、`Started ...` の表示を待ってから開き直してください |
| 起動時にデータベースの接続エラーが出る | PostgreSQL が起動していない | `brew services start postgresql@16` を実行してください |
| 同上（`role "postgres" does not exist`） | 接続用ユーザーがない | 2-5 の ① を実行してください |
| 同上 | データベースがない | 2-5 の ② を実行してください |
| 同上 | ユーザー名・パスワードが違う | 下の「接続設定を変える」を見てください |
| 起動時に `Port 8080 was already in use` と出る | 前に起動したアプリが動いたまま | 前のアプリを `control` + `C` で止めてから、もう一度起動してください |
| `./mvnw: Permission denied` と出る | 実行の許可がない | `chmod +x mvnw` を実行してから、もう一度起動してください |
| ログインできない | メールアドレスかパスワードの入力ミス | 大文字・小文字や、余分なスペースがないか確認してください |
| 収支入力でカテゴリーや資産が選べない | まだ登録していない | 「5-1」「5-2」の手順で先に登録してください |
| CSV 取込でエラーになる | ファイルの形式が違う | PayPay の利用明細 CSV（UTF-8、5MB 以下）か確認してください |
| カテゴリーの「削除」ができない | 記録で使われている | 「無効化」を使ってください（7-1 参照） |

### 接続設定を変える

アプリは、ユーザー名 `postgres`・パスワード `postgres` でデータベースに接続します。
ご自分の PostgreSQL の設定と違う場合は、`src/main/resources/application.properties` の次の行を書き換えてから起動してください。

```properties
spring.datasource.username=postgres
spring.datasource.password=postgres
```

### 11-2. プログラムの構成

「画面とのやりとり」「処理のルール」「データの保存」を分けています。
どこに何が書いてあるかがわかりやすく、修正したときに他の部分へ影響しにくいためです。

```
ブラウザ → controller（受付係）→ service（担当者）→ repository（倉庫係）→ データベース
```

```
src/main/java/com/example/shibakamio2026/
├── controller/   # 画面からのリクエストを受け取り、表示する画面を決める
├── service/      # 残高の計算、CSV の読み込み、固定費の予定作成などの処理
├── repository/   # データベースへの保存・取得
├── entity/       # テーブルと対応するクラス
├── dto/          # 入力フォーム・画面表示用のクラス
├── enums/        # 決まった選択肢（収入/支出、資産種別 など）
├── config/       # ログインまわりの設定
├── exception/    # 独自のエラー
└── web/          # ログイン中のユーザー取得などの共通処理

src/main/resources/
├── templates/    # 画面の HTML
├── static/css/   # 画面の見た目
├── schema.sql    # テーブル作成（起動時に自動実行・無い場合のみ作成）
├── data.sql      # お試し用データ（起動時に自動実行・無い場合のみ登録）
└── application.properties  # 接続先などの設定
```

### 11-3. データベースのテーブル

| テーブル | 保存する内容 | 分けている理由 |
| --- | --- | --- |
| `users` | ユーザー | 誰のデータかを区別するため |
| `assets` | 資産 | 置き場所ごとに残高を計算するため |
| `categories` | カテゴリー | ユーザーごとに自由に追加・変更できるようにするため |
| `transactions` | 実際の収入・支出 | 家計簿の中心となる記録 |
| `transfers` | 資産間の移動 | 収支とは違い、全体のお金は増えも減りもしないため |
| `auto_transactions` | 固定費の「ルール」 | ルールと、そこから作られる 1 回ごとの予定を分けるため |
| `scheduled_transactions` | ルールから作られた 1 回ごとの予定 | 「予定」「確定」「キャンセル」の状態を 1 回ずつ持たせるため |
